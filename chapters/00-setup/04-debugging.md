# 0.4 在 VS Code 里调试

> 这一节要解决的问题：代码结果不对时，与其到处加 `console.log`，不如让程序停下来，直接看每个变量的值。

`console.log` 当然有用，但每看一个新变量就要改代码、重跑一次。调试器可以让程序在任意一行暂停，你能看到这一刻 **所有** 变量的值、函数是怎么一层层调用过来的，还能一行一行地往下走。等到第 6 章调试 agent 的消息循环时，你会非常庆幸早早学会了它。

本仓库已经在 `.vscode/` 里准备好了调试配置。第一次打开仓库时，VS Code 会提示安装推荐的扩展，建议全部安装（其中 "TypeScript 7" 扩展让编辑器使用和命令行相同的 TypeScript 7；安装后如果没有自动启用，在命令面板运行 `TypeScript: Enable TypeScript 7`）。

## 方法一：JavaScript Debug Terminal（最简单）

1. 打开命令面板（macOS `Cmd+Shift+P`，Windows/Linux `Ctrl+Shift+P`）
2. 运行 `Debug: JavaScript Debug Terminal`，会打开一个特殊的终端
3. 在代码里打好断点（在行号左侧点一下，出现红点）
4. 在这个终端里照常运行命令：

   ```bash
   pnpm tsx chapters/00-setup/examples/03-debug-me.ts
   # 或者
   node chapters/00-setup/examples/03-debug-me.ts
   # 甚至是跑测试
   pnpm ex 00-setup --run
   ```

在这个终端里启动的任何 Node.js 进程都会自动连上调试器。不需要任何配置，这是最推荐的方式。

## 方法二：F5 启动（用仓库里的 launch.json）

打开要调试的文件，按 `F5`（或左侧"运行和调试"面板），从下拉框里选择一个配置：

| 配置                             | 适用场景                                           |
| -------------------------------- | -------------------------------------------------- |
| 调试当前文件（Node 原生运行 TS） | 调试示例和普通脚本                                 |
| 调试当前文件（tsx）              | 文件用了 Node 原生不支持的语法时（本仓库不会出现） |
| 调试当前测试文件（Vitest）       | 打开一个 `.test.ts` 文件，调试其中的测试           |

为什么 Node 原生运行 TS 时断点能准确停在源码上？0.2 节讲过：Node 只是把类型标注替换成空格，每一行、每一列的位置都没变，调试器看到的代码和你写的完全对得上。tsx 会改变代码位置，但它会生成 source map（源码映射）告诉调试器怎么对应回去，所以同样可以正常调试。

## 方法三：Vitest 扩展

安装推荐的 Vitest 扩展后，测试文件里每个 `test(...)` 左边会出现运行按钮，右键可以选择 "Debug Test"。左侧的"测试"面板也能看到所有测试的状态。做练习时这是最顺手的方式。

## 调试器的基本操作

程序停在断点后：

| 操作     | 快捷键      | 作用                                     |
| -------- | ----------- | ---------------------------------------- |
| 继续     | `F5`        | 一直运行到下一个断点                     |
| 单步跳过 | `F10`       | 执行当前行，停在下一行（不进入函数内部） |
| 单步进入 | `F11`       | 如果当前行调用了函数，进入那个函数       |
| 单步跳出 | `Shift+F11` | 执行完当前函数，回到调用它的地方         |
| 停止     | `Shift+F5`  | 结束调试                                 |

左侧面板里最有用的三块：

- **VARIABLES（变量）**：当前作用域里所有变量的值，对象可以展开
- **WATCH（监视）**：添加任意表达式，比如 `turn.text.length`，每一步都会重新计算
- **CALL STACK（调用栈）**：当前函数是被谁调用的，点击可以跳到调用方查看当时的变量

还有两个实用技巧：

- **条件断点**：右键断点 → 编辑断点，填写条件如 `turn.role === "assistant"`，只在条件成立时暂停
- **`debugger;` 语句**：在代码里写一行 `debugger;`，调试器连着的时候会停在这里，相当于用代码打断点

## 动手：调试练习场

打开 [examples/03-debug-me.ts](examples/03-debug-me.ts)，按照文件顶部注释的 5 个步骤操作一遍。目标不是找 bug，而是熟悉上面那些按钮和面板。

## 练习：用调试器修 bug

[exercises/00-setup/02-word-count.ts](../../exercises/00-setup/02-word-count.ts) 里有两个函数，**代码已经写好了，但有 bug**，测试会失败。

1. 运行 `pnpm ex 02-word-count`，看看哪些测试失败了
2. 用上面任意一种方法调试失败的测试，在函数里打断点，观察中间变量的值
3. 找到原因，修好代码，让测试全部通过

提示：不要只盯着代码"读"出 bug，试着让调试器告诉你 `split` 之后数组里到底有什么。

## 小结

- 最省事的调试方式是 JavaScript Debug Terminal：在里面运行任何命令都自动连上调试器
- 仓库提供了三个 F5 配置：Node 原生、tsx、Vitest 测试
- 熟练使用断点、单步执行、变量 / 监视 / 调用栈面板，以及条件断点和 `debugger;`

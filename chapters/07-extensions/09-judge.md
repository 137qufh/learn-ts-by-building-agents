# 7.9 评判与回归

> 这一节要解决的问题：有些好坏写不成 `includes`。"这段总结有没有漏掉决定"就是这种。让一个模型打分可以，但分数本身不是真相。怎样才算退步，才不会把噪声当成回归？

示例代码：[examples/09-judge.ts](examples/09-judge.ts)

## 裁判的输出是不可信文本

让模型按量表打分，它返回的是一段文字。可能包在 ` ```json ` 里，也可能前后有"好的，我来打分"。这是模型输出，用 [5.5 节](../05-validation/05-model-output.md) 的态度：先抽出一个 JSON 对象，再检查形状。解析失败是 `{ ok: false, error }`，不要抛。调用方要把"裁判没按格式说"和"被评的答案很差"分开。前者是评测设施坏了，后者是产品退步了，修的不是同一个地方。

抽出对象的办法要窄：优先用代码块里的正文，否则用第一个 `{` 到最后一个 `}`。找不到就 `无法解析评测结果：找不到 JSON 对象`。`JSON.parse` 自己的错误也包上同一句前缀，调用方只看前缀就知道是解析失败。

量表是你写的准则名单。检查按这个顺序，命中一条就停：

1. 没有 `scores` 数组
2. 某一条不是带字符串 `criterion` 的对象
3. 同一个准则出现两次
4. `score` 不是整数 0、1 或 2。字符串 `"2"` 不行，`1.5` 不行，`3` 不行
5. `reason` 不是非空字符串。只有空格也不行
6. 有量表里没有的准则
7. 缺了量表里的准则，按名单的顺序报第一个

成功时 `scores` **按量表的顺序** 排，不按模型写的顺序。`mean` 是算术平均，不四舍五入。示例里 2 和 1 的平均打印为 `mean 1.5`。顺序固定，平均才不会因为模型把两项写反了而在别的地方对不上。

字符串 `"2"` 被拒绝，和第 5 章不用 `z.coerce` 是同一条。合不合法是量表的约定。悄悄转成数字，一个格式错误的裁判会得到一个看起来合法的高分。

## 容忍度的边界是"超过"，不是"达到"

基线是 2，容忍度是 1。

- 这次是 1：下降了 1，`1 > 1` 不成立，`{ ok: true }`。抖动刚好吃满容忍度，还不算回归
- 这次是 0：下降了 2，`2 > 1`，回归一条 `{ name: "总结", before: 2, after: 0, delta: -2 }`

`delta` 用这次减去上次，退步就是负数。把比较写成 `>=`，第一种也会变红。练习把这两种都钉住了。

分数 `3` 即使 `reason` 写得很认真，也是 `评分项 "准确" 的分数必须是 0、1 或 2`。量表只有三档。多出来的一档让不同裁判的 2 和 3 没法比。`1.5` 同样拒绝：整数这个约定一旦松开，四舍五入发生在哪一层就得再争一次。

## 裁判会错

就算格式对了，分数仍然可能错。用它做门禁之前，至少要知道这些：

- 它偏好写得长的、语气像它自己的答案
- 同一份答案，放在量表的不同位置，分数会变
- 温度不为 0 时，同一份答案两次分数不同
- 裁判和被评的是同一个模型时，它容易给"像自己"的答案更高分

所以能用 7.8 的断言写死的，不要问裁判。要用，就先准备一小批你已经知道好坏的样本，看裁判在这批上是否和你一致。这批样本没过，不要用它的分数挡合并。

课程的 `parseJudge` 不调用模型。它只解析文本。文本可以来自假模型，也可以在设置了 `OPENAI_API_KEY` 和 `OPENAI_MODEL` 时来自真正的模型。门禁不依赖那一次调用有没有发出去。

## 回归是"比上次差"，不是"低于一个常数"

`compareBaseline(current, baseline, tolerance = 0)` 拿这次的均分和存下来的基线比。

下降 **超过** 容忍度才记一条回归：`before - after > tolerance`。刚好等于不算。`tolerance` 是 1、从 2 掉到 1，差是 1，不是回归；掉到 0，差是 2，才是。把 `>` 写成 `>=`，刚好等于容忍度的波动会变红，练习 7-9 的那条就是在抓这个。

`delta` 记的是 `after - before`，所以退步是负数。报告里同时给 `before` 和 `after`，读的人不用在脑子里减。

另外两条：

- 这次多出来的用例不算问题。你加了一条新评测，不该被说成退步
- 基线里有、这次没有的名字放进 `missing`，按基线的顺序。丢了用例是评测变少了，不是产品变好了
- 两边都没有问题才是 `{ ok: true }`。有回归、有缺失，或者两个都有，都是 `{ ok: false, regressions, missing }`

名字重复、`mean` 不是有限数字、`tolerance` 不是非负有限数字，都是调用错误，直接抛。`NaN` 比大小永远是 false，一条 `NaN` 的分数会悄悄不算回归。与其让它混进报告，不如拒绝。

容忍度是给裁判的抖动留的，不是给"差不多就行"留的。7.8 那种确定性断言，容忍度应该是 0：假模型的轨迹掉了一点，就是掉了。换了嵌入模型（7.7 节）之后，旧基线不再描述同一个系统，要重新采一版基线，而不是把容忍度调到大得什么都过。

解析失败的 `error` 一律以 `无法解析评测结果：` 开头，后面是具体原因，例如 `找不到 JSON 对象`。缺字段、分数不合法则不用这句前缀，直接说 `评测结果缺少 scores` 或 `评分项 "准确" 的分数必须是 0、1 或 2`。两句前缀不同，调用方不用再去猜是 JSON 坏了还是量表没对上。成功时的 `mean` 用除法，不 `Math.round`。2 和 0 的平均是 1，2 和 1 的平均是 1.5。四舍五入会把 1.5 收成 2，一次没变的评分在基线比较里看起来像涨了一档。

## 停下来想一想

1. 裁判返回 `{"scores":[{"criterion":"准确","score":"2","reason":"好"}]}`。这是答案差，还是评测设施坏了？`parseJudge` 应该抛异常，还是 `{ ok: false }`？
2. 容忍度是 1，分数从 2 变成 1。算不算回归？从 2 变成 0 呢？为什么"超过"和"达到"差这一条？

基线里有、这次跑丢了的名字进 `missing`，按基线原来的顺序，不算进 `regressions`。这次新加的名字既不进回归也不进缺失。评测变多是好事，评测变少不是"产品变好了所以少了一条失败"。两边都空才是 `{ ok: true }`。只检查回归、忘了缺失，删掉一条用例也能得到绿的报告。

名字在 `current` 或 `baseline` 里重复，抛 `Error`，消息里有那个名字。`mean` 不是有限数字，或者 `tolerance` 是负数、`NaN`，抛 `RangeError`。`NaN > 0` 是 false，一条坏分数会悄悄不进回归。拒绝它，比在报告里解释 `NaN` 便宜。默认容忍度是 0：不传第三个参数时，任何下降都是回归。7.8 的确定性用例就该用这个默认值。

多余的准则按出现顺序列出来，用 `JSON.stringify` 包上再以逗号加空格连接。缺的准则按量表的顺序报第一个，不把所有缺项一次列完。先报多余还是先报缺少，取决于检查顺序：先看模型多给了什么，再看量表里还缺什么。换这个顺序，练习里"多余的评分项"那条的文案会对不上。

`tolerance` 默认参数是 0。调用时不传，任何下降都是回归。传 `undefined` 会触发默认参数，变成 0。不要在函数体里再写 `tolerance || 0`：`NaN` 是假值，`NaN || 0` 会变成 0，一条本该抛掉的容忍度会变成"任何下降都算回归"。`??` 替换不了 `NaN`。检查 `Number.isFinite` 并且拒绝负数，比再补一层默认值清楚。0 本身是合法的容忍度，不能因为 0 是假值就把它换成别的数。

负的容忍度没有意义：它会把"没变"也算成下降。所以直接抛，而不是取绝对值。

## 小结

- 裁判的输出按不可信文本解析。失败是结果，不是异常
- 分数必须是整数 0、1、2。字符串、小数、超出范围都拒绝。理由不能是空白
- 成功时按量表排序，`mean` 不四舍五入
- 裁判会偏、会抖、会偏向自己。先用已知样本检查它，再谈用它做门禁
- 回归看的是相对基线的下降，而且要 **超过** 容忍度。新用例不算退步，丢了旧用例算。确定性断言的容忍度是 0

代码块优先于"第一个大括号到最后一个大括号"。模型先写了一段 `{` 举例，再给真正的围栏 JSON 时，先切围栏才不会把两段拼成一个非法的对象。没有围栏，才退回找大括号。

# 7.7 检索：关键词和本地向量

> 这一节要解决的问题：笔记多了以后，不能把全部塞进提示。关键词对"牛奶"很够用，对"乳制品"就不够。向量检索通常要一个 embedding 模型，这一章又不能联网。接口该怎么留，才不用等模型？

示例代码：[examples/07-retrieval.ts](examples/07-retrieval.ts)

## 两路分数

检索返回的是排序，不是布尔值。这里用两路，各占一半：

- **关键词**：查询的片段里，有多少出现在文档里。上一节的词和二字片段。查询没有片段时这一项是 0
- **向量**：两段文本各变成一个等长的数组，用余弦相似度。余弦在 -1 到 1，先变成 `(cos + 1) / 2` 再和关键词平均，这样两路都在 0 到 1

余弦的定义是点积除以两个向量的长度。长度不同是调用错误。任一向量全是 0（空文本）时，除数是 0，规定结果为 0，而不是 `NaN`。

## 不联网的向量

真正的 embedding 模型把"牛奶"和"乳制品"放在附近。那需要一次模型调用，和"评测、练习都能离线跑"冲突。默认实现用哈希：

1. 用和记忆检索相同的片段
2. FNV-1a 把片段散到固定数量的桶里（默认 32）
3. 哈希的最低位决定这个桶加 1 还是减 1，碰撞可以互相抵消
4. 做 L2 归一化。不归一化的话，长文档的数字更大，余弦会被长度支配

同样的文本永远得到同样的向量。示例里"牛奶"和自己的余弦是 1，和"牛奶盒"比和"量子"更近，空文本的余弦是 0。

这套东西 **记不住同义词**。"牛奶"和"乳制品"如果没有共同片段，就只靠碰巧落在同一个桶。桶少的时候，不相干的词也会撞在一起。它证明的是接口：`Embedder` 只有一个 `embed(text)`。测试注入一个假的，看排序；真正要语义时，换成调用模型的实现，`createRetriever` 的调用方一行都不用改。换模型之后分数会变，评测（下一节）负责告诉你变好了还是变差了。

归一化之后，"cat" 和 "cat cat" 的方向一样，次数被抹掉了。次数如果重要，靠关键词那一路，或者不要归一化并接受长文档占优。这里选择归一化，把这个限制写在明处。

## 小结

- 分数是关键词重叠和余弦各一半。空向量的余弦定义为 0
- 默认向量是哈希加归一化，离线、确定、没有同义词
- `Embedder` 是可替换的。语义检索换实现，不改调用方
